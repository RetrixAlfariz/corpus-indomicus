# Schema migrations

Registry initialization upgrades SQLite `user_version` to 2. It retains existing runs, segments, instruments, observations, objects and manifests. Added run columns are `scope_json`, `scope_fingerprint`, `frozen_at`; manifests add `metadata_json` and `detail_sha256`. New tables are `discovery_partitions`, `discovery_memberships`, `document_files` and `source_fetch_events`. Repeated initialization is safe. Old rows without an acquisition detail hash have no inferred per-run file inventory; global objects/provenance remain available until re-observed.

New instrument identity is source-scoped (`provider:source:<source_id>`). The old `idx_instrument_identity` unique index is replaced by a nonunique issuer-aware lookup index. Old IDs and historical links are preserved; re-observing a source creates/links its source-scoped row. Previously merged historical instruments cannot be reconstructed without revisiting source evidence. New rows retain `legacy_identity_candidate` and, when available, an issuer-qualified candidate. Neither is used to force cross-source merging.

Storage receipts replay on startup after an object/SQLite crash. Original bytes remain unchanged. An archive lock serializes writers; retry reuses state without deleting history. Old manifests can be processed after all legacy segments are complete; category-aware discovery creates a scoped run rather than inventing classification for old checkpoints. Back up the registry and object directory before upgrading a valuable existing collection; downgrading software against the upgraded registry is unsupported.
