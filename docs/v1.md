# v1 completion contract

Corpus Indomicus supports systematic acquisition of the central and ministry/institution inventories. Regional acquisition is deferred. Repealed, replaced and inactive instruments remain in scope; status is metadata.

## Default scope

- source: JDIH BPK
- categories: central and ministry/institution, resolved from the live authoritative catalog
- range: all available years by default; `--from-year`/`--to-year` provide bounds
- cutoff: the manifest is finite once discovery finishes
- originals: PDF source bytes are retained in v1 as ground truth for v2

## Delivered capabilities

- configuration/setup
- range or `--all` finite snapshot backfill
- category-aware `catalog types`, `plan`, `discover`, and `ingest --run-id` workflow
- category/type/optional-year/page checkpoints and scope-safe resume
- persisted manifest items and retryable failure state
- incremental sync with a configurable overlap window
- bounded ingestion from a frozen manifest and status/coverage JSON
- source-record, legal-instrument and SHA-256 object identity separation
- exact object deduplication
- compact lossless HTML/JSON/text storage
- PDF signature/MIME validation
- neutral cross-document reference observations
- storage safety reserve
- corpus/PDF/storage metrics
- object integrity verification
- low-level BPK development commands retained for debugging

PDF validation checks the PDF signature and EOF marker plus response metadata; it is not a full PDF syntax validator. Acquisition statuses include `pending`, `running`, `done`, `no_file`, `failed`, `partial`, and `unresolved`. Retry covers failed, partial, no-file and unresolved work when requested.

`out_of_scope` preserves evidence of regional/year mismatches without downloading their PDFs. A run can finish with known `no_file` records; its coverage report still exposes them. Failed, partial, unresolved or pending work keeps the run incomplete. See [CLI](cli.md), [migration](migrations.md) and [validation evidence](validation.md).

## Intentionally deferred to v2

- PDF text-layer inspection and extraction
- OCR
- layout reconstruction
- canonical document AST
- Markdown rendering
- semantic legal-relation interpretation
- source-blob eviction policy based on representation fidelity

The v1 pilot corpus is the validation ground truth for those v2 features.
